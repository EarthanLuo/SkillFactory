# Evolution

## Trigger

首次重任务测试虽然把检索和分析交给 ChatGPT 会话，但完整长报告又被读回 Codex 主会话，未充分缓解主会话 token 与上下文压力。用户明确将核心目标定义为利用 GPT 聊天的检索能力分担 Codex，并允许把聊天视为受限子 Agent 进行适当放权。

## Problem

旧 Skill 对研究过程和逐项完整输出约束过多，聊天缺少在范围内自主选择检索策略与证据的空间；回收又偏向全量报告，抵消了上下文隔离收益。

## Previous Behavior

Codex 主任务规定较细的研究字段，聊天执行后返回完整结果；主任务通常读取整份回答并重新核验与总结。

## New Behavior

- 将聊天明确为受限研究子 Agent，可在既定范围内自主调整查询、筛选和替换来源、比较证据并选择停止点。
- 项目目标、外部动作、文件修改、敏感信息、付费操作和最终决策仍保留在 Codex 主任务与用户授权范围内。
- 任务包新增研究模式、委派权限、回传预算和证据预算。
- 默认只回收紧凑决策包；详细搜索过程和完整资料表留在目标聊天，需要时以定向追问获取。
- 主任务按风险抽样核验一至三个关键点，不再默认完整复查。
- 清洗脚本的终端输出只返回计数和缺失信号；完整链接列表留在 JSON 报告文件中。

## Reason

把研究策略与中间材料留在隔离聊天，同时限制回传粒度，才能真正减少 Codex 主会话重新摄入的上下文，而不仅是转移计算位置。

## Alternatives Considered

- 继续要求完整报告：未采用，因为会把大量结果重新灌回主会话。
- 完全放弃核验：未采用，因为外部聊天结果仍是不受信输入。
- 允许聊天直接修改项目：未采用，因为研究委派不等于转移项目写权限。

## User Confirmation

用户明确回复：“按研究子 Agent 方案修订”。
