# Evolution

## Trigger

In real use, `reverse-experience` successfully wrote a Source and Extraction but ended after reporting the files. It put unresolved judgment into a Discussion document without actually discussing it with the user.

## Problem

The old instructions defined the disk artifacts and prohibited automatic adoption, but did not define a conversational completion condition. They also did not explicitly prohibit creating a Discussion or decision before the user responded.

## Previous Behavior

Write the Source and Extraction, then optionally suggest `internalize-experience` as a later user-triggered action.

## New Behavior

After writing the artifacts, summarize the extraction, surface one to three context-dependent tensions, and end with one concrete question that invites the user to continue. Before the user responds, do not create a Discussion, invent a user position, or select an internalization decision.

## Reason

The extraction should remain durable and traceable while unresolved judgment returns to the conversation where the user can participate, correct assumptions, and decide whether to internalize the experience.

## Side Effects

The extraction now normally ends with an additional conversational turn. The three Factory Skills remain separate and user-triggered; the handoff does not automatically invoke `internalize-experience` or authorize a Portable Skill change.

## User Confirmation

The user explicitly confirmed the proposed change by replying “修改”.
