# Evolution

## Trigger

真实替身测试中，首次结果超过提交预算后触发了二次压缩。用户指出，多次压缩会丢失信息，并增加时间和 token 成本；同时桌面助手消息需要按 `agentMessage` 类型可靠提取。

## Problem

旧技能把提交预算同时作为接收硬门槛，普通超限也会触发第二次聊天交互。提取约定也没有明确禁止通过字段路径猜测消息角色。

## Previous Behavior

超预算答案不得进入主会话，并应在同一聊天要求压缩后再次回收。预算命令会生成压缩请求。桌面消息虽然由脚本支持 `agentMessage`，但技能没有明确角色识别规则，也没有覆盖等价 assistant role 结构。

## New Behavior

提交预算继续作为替身的强写作约束。接收端测量并报告实际偏差，但普通超限仍一次回收，不自动压缩、重写或重试。只有用户明确要求、回复被截断或宿主硬安全上限阻止安全回收时，才允许跟进。脚本预算报告声明 `accept_and_report`；可选压缩文件只在明确调用参数时生成，并标记需要显式请求。提取器按 `agentMessage`、`assistantMessage` 或等价 role 识别助手正文。

## Reason

保持一次任务提交和一次最终回收，可避免压缩造成的信息损失与额外交互成本，同时保留预算测量的可观察性和前置正文隔离。

## Alternatives Considered

保留硬预算门槛并提高阈值仍可能触发多轮；自动本地截断会静默丢失结论；自动让聊天重写仍增加成本，因此均未作为默认行为。

## User Confirmation

用户明确要求：“提交任务时限制预算，但是接收时不严格限制……修复技能缺陷”。
