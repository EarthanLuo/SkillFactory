# Evolution

## Trigger

真实测试中，既有 ChatGPT 会话的任务发布和回收链路跑通，但任务包构造与结果清洗仍由 Agent 临时完成，回收内容包含内部引用占位符、跟踪参数和可能的重复正文。

## Problem

重复且确定性的文本加工占用 Agent 上下文，并容易在不同执行中产生格式差异；同时不能让本地脚本越权接管桌面聊天、发送、等待或采信判断。

## Previous Behavior

Skill 仅用文字列出任务包字段与回收检查要求，由 Agent 每次自行生成任务编号、组织提示词并清洗返回内容。

## New Behavior

Skill 内新增无网络 Python 脚本 `scripts/stand_in_package.py`：

- `prepare` 从结构化 JSON 生成带唯一编号和返回契约的 Markdown 任务包；
- `clean` 清除已知内部引用占位符、常见链接跟踪参数和完全重复段落，并输出 JSON 检查报告；
- Agent 仍负责选择聊天、取得授权、发送、等待、核验事实和决定是否采用；Python 不可用时按原有手动路径降级。

## Reason

将稳定、可重复验证的文本变换交给脚本，可以降低格式漂移和上下文消耗，同时保留所有外部动作与认知判断的授权边界。

## Alternatives Considered

- 自动轮询或发送：未采用，因为本地脚本不能可靠访问桌面应用的原生会话工具。
- 中央任务状态机：未采用，避免引入自动阶段转换和额外状态依赖。
- 将核验结论自动化：未采用，事实可信度与任务适用性仍需 Agent 判断。

## User Confirmation

用户在看到 `prepare + clean` 两模式、无自动轮询和无状态管理的提案后明确回复：“可以”。
