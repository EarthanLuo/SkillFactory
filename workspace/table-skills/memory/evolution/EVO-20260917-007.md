# Evolution

## Trigger

单轮替身测试成功，但最终正文把 12 个 GPT 桌面内部引用占位符带入主会话，且没有普通 URL。

## Problem

旧流程把占位符清理放在可选的后续 `clean` 步骤。使用宿主侧组合直接回收正文时，原始占位符可能先进入主会话，之后再清理已经无法收回上下文成本，也会降低证据可读性。

## Previous Behavior

`extract` 原样写出助手正文，只返回字符数和链接数。内部引用占位符需要另行运行 `clean` 才会删除。技能没有明确要求宿主侧组合在输出正文前执行同样清理。

## New Behavior

`extract` 在写出答案前删除 `:chatgpt-content-reference{...}`，并返回移除数量和普通链接缺失信号。技能要求任何宿主侧组合也必须在向主会话输出正文前清除这些标记。缺少普通链接会被记录为证据限制，但不会自动触发第二次聊天交互。

## Reason

前置确定性清理能够保护主会话上下文和可读性，同时保留一次提交、一次回收的低交互策略。

## Alternatives Considered

接收后再清理无法挽回已进入主会话的占位符；自动要求替身补发链接会恢复多轮成本；尝试从内部索引猜测 URL 不可靠。因此只删除不可用标记并显式报告证据缺口。

## User Confirmation

用户在看到测试反馈和建议后明确回复“修订”。
