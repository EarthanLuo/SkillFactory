# Evolution

## Trigger

第二次替身测试暴露正文轮询回灌旧内容后，进一步讨论了哪些固定操作可以在模型读取原始响应之前脚本化。用户确认修改技能。

## Problem

现有脚本只有任务包生成和最终文本清洗。状态判断、目标轮次选择、完整载荷预算检查和任务记录仍可能要求主会话读取原始对话结构，无法稳定兑现上下文隔离。

## Previous Behavior

宿主或主任务读取对话响应后自行判断状态、找到匹配答案、检查长度并记录执行信息。即使随后运行清洗脚本，原始长内容也可能已经进入模型上下文。

## New Behavior

- `probe` 将直接对话响应或工具封装缩减为状态、最新 turn ID 等元数据。
- `extract` 根据任务 ID 和可选基准 turn ID 选择一个已完成回答，正文只写文件，终端只输出计数。
- `budget` 按完整字符、链接数和启发式 token 估算执行预算闸门；超限时只生成固定压缩请求。
- `ledger` 追加任务局部观察事件，不推断状态转换、不触发动作。
- Skill 明确这些过滤必须发生在原始响应暴露给模型之前才有 token 收益。
- 自动发送、网络访问、持续轮询、事实核验和结论采信仍不属于脚本权限。

## Reason

把确定性的解析和计数放在模型之前，可以让主会话只看到短元数据和合格的决策包，直接减少预览、旧轮次、重复封装和超预算回答造成的上下文消耗。

## Alternatives Considered

- 只增强最终清洗：未采用，因为无法消除已经进入主会话的原始响应。
- 让脚本直接控制聊天和持续轮询：未采用，因为会扩大外部动作权限并增加重复发送风险。
- 建立中央任务状态机：未采用；使用只追加、不推断转换的任务局部事件日志。

## User Confirmation

用户在审阅 `probe + extract + budget + ledger` 建议后明确回复：“修改技能”。
