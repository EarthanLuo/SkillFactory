# Feedback

## Skill Used

`reverse-experience`

## Situation

用户复核原作者 README 后，检查既有 Source 与 Extraction 对“网页替身”省 token 结果的表述。

## What Happened

来源中的负面结果原本只适用于 Astar 模型，但 Source 摘要丢失了这一模型限定；Extraction 又继承该摘要，把局部结果表述成网页替身整体的省 token 效果不理想。

## Good Experience

来源、提取和不确定性均有可追溯记录，因此能够定位泛化从 Source claim 阶段开始，并修正下游 Extraction。

## Bad Experience

- 模型范围在摘要时丢失。
- 特定条件下的性能结果被外推为方案级判断。
- 技能虽要求识别情境限制，但没有把模型、版本、环境、时间、比较基线和量词列为必须保留的主张边界。

## User Interpretation

用户确认省 token 不理想只发生在 Astar 模型，并认为网页替身现在仍有思路参考价值；用户要求修复技能缺陷和原有记录。

## Other Notes

修复应保持来源主张、用户核验和新的迁移推断分层。局部失败不能证明整体无效，设计仍有参考价值也不能反过来证明其在其他模型上能够省 token。
