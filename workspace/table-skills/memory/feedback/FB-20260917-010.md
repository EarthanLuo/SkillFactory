# Feedback

## Skill Used

`web-task-stand-in`

## Situation

连续真实测试中，主会话仍需逐次发起状态探测，虽然探测只返回短元数据且不增加聊天对话轮次。

## What Happened

桌面聊天在任务完成后常有几十秒回合列表同步延迟，导致主会话通常要发起两次状态探测才能看到新回合。原始正文已被宿主侧过滤，但等待调度和每次探测的工具交互仍属于主会话工作。

## Good Experience

现有探测不会泄漏旧正文，基线回合和任务 ID 能可靠避免误收旧答案。

## Bad Experience

主会话仍承担等待、判断是否继续探测和再次调用工具的成本；这不符合把替身当作独立研究子 Agent 的目标。

## User Interpretation

用户明确要求改成“宿主侧等待脚本”，让一次宿主调用内部完成低频状态检查，只在完成或超时后向主会话返回一次结果。

## Other Notes

普通本地 Python 脚本不能直接访问桌面原生对话工具。可移植实现需要由宿主注入 `readThread` 适配器，并确保内部读取结果不被逐次输出给模型。
