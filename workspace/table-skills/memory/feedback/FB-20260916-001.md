# Feedback

## Skill Used

`reverse-experience`

## Situation

用户用该 Factory Skill 逆向提取 `duoduoler-ops/Table-skills` 中可迁移的经验，希望先得到有来源依据的提取，再继续讨论这些经验是否适合自己的情境。

## What Happened

Skill 成功创建了 Source 与 Extraction，但没有在完成提取后继续向用户发起讨论。它把原本需要与用户共同判断的内容写入了 Discussion 文档，然后直接报告落盘结果并结束。

现有 `DSC-20260916-001` 明确写着“用户尚未提供额外立场”，却仍代替用户形成了初步内化结论 `TEST`。因此，文件中的“讨论”并不是实际发生过的用户讨论。

## Good Experience

来源与提取确实完成并落盘，Source、Extraction 和索引结构可追溯；用户确认“它确实是提取了”。

## Bad Experience

- 用户没有得到预期的后续互动，流程在展示文件后中断。
- 应由对话完成的问题、分歧和情境判断被静态写进文档，用户失去参与和纠正的机会。
- 未发生的讨论被记录成 Discussion，并产生了一个并非用户作出的 `TEST` 决定，削弱了 provenance。

## User Interpretation

第一个 Factory Skill 只完成了“提取并落盘”，却没有把需要讨论的内容带回对话继续和用户讨论；流程设计或结束条件缺少明确的交互交接。

## Other Notes

修正时应保留 Source 与 Extraction 的可靠落盘，也应继续遵守“不自动采用经验、不自动创建 Portable Skill”的边界。需要区分“在当前回复中邀请并开始讨论”与“自动调用另一个 Factory Skill”：前者是恢复用户参与，后者仍不应发生。
