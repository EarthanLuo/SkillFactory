# Feedback

## Skill Used

`web-task-stand-in`

## Situation

确认当前桌面工具不能通过原生创建接口新建普通 ChatGPT 快速聊天，但 Skill 需要一个明确、低歧义的首次启动路径。

## What Happened

此前 Skill 只说宿主不能创建时选择现有聊天，或在没有路由时提供手工任务包。它没有明确指导用户先在桌面应用中创建普通 ChatGPT 聊天，再把该会话交回主会话。

## Good Experience

已有会话引用可以被主会话识别、发送任务并回收结果，真实测试已验证这条路线可用。

## Bad Experience

首次使用者可能不知道应创建 ChatGPT Chat、ChatGPT Work 还是 Codex 任务，也不知道创建后需要通过会话引用、链接、标识符或精确标题告诉主会话。

## User Interpretation

用户明确要求给 Skill 增加引导：先让用户创建一个聊天会话，然后告诉主会话。

## Other Notes

人工引导不应声称已自动创建，也不应把 API `conversations.create` 产生的服务端对象当作桌面聊天。
