# Feedback

## Skill Used

`web-task-stand-in`

## Situation

按“提交预算、接收不硬拦截”的新规则，再次向既有 GPT 桌面聊天提交 3DGS 压缩与移动端部署文献任务，并测量主会话与账户用量变化。不测试 Astra。

## What Happened

只发送一次任务、等待状态变化后只回收一次。替身返回 3,229 字符、启发式估算约 1,220 token，未截断，略超提交目标 3,000 字符；主会话仍直接接收，没有触发压缩或重试。提交前后账户窗口均为五小时 48%、周窗口 38%。

## Good Experience

单轮交互成功，避免了前一轮的二次压缩等待与额外聊天成本。状态探测和回收均在工具内部抑制了原始会话包装和旧回合正文。

## Bad Experience

回收正文残留 12 个 `:chatgpt-content-reference{...}` 内部引用占位符，且可提取 URL 数为 0，降低了证据可读性。提交预算只能作为软约束；本轮实际结果比目标多 229 字符。账户百分比无变化，无法证明单任务 token 节省。

## User Interpretation

用户关心单轮交互是否降低主会话 token 压力。当前结果支持“单轮与上下文隔离可行”，但不支持从账户整数百分比推断精确节省。

## Other Notes

后续若修订，应优先处理桌面内部引用占位符的回收前清理或呈现策略；不应因此恢复自动压缩或多轮交互默认值。
