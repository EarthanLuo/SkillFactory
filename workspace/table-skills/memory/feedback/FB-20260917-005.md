# Feedback

## Skill Used

`web-task-stand-in`

## Situation

讨论在已修复等待与回收协议之后，还能把哪些固定操作转为脚本，以继续减少 Codex 主会话的 token 消耗。

## What Happened

现有脚本只负责准备任务包和清洗最终文本。状态探测、精确结果选择、完整载荷预算检查和任务事件记录仍需要主会话解释原始结构化响应，可能再次摄入预览、旧轮次或超长结果。

## Good Experience

已有 `prepare` 和 `clean` 证明确定性文本处理适合留在本地脚本中，而且可以让终端只返回短摘要。

## Bad Experience

缺少位于模型读取之前的过滤步骤。若原始对话响应已经进入主会话，再执行清洗无法收回已经消耗的上下文。

## User Interpretation

用户确认修改技能，将状态过滤、结果提取、预算闸门和任务事件记录脚本化；研究判断、发送授权、来源可信度判断和最终采信仍保留给主任务。

## Other Notes

脚本应只做确定性处理，不自动发送消息、不持续轮询、不自动改变任务阶段，也不把任务记录扩展为中央状态机。
