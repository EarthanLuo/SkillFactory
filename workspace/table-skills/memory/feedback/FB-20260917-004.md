# Feedback

## Skill Used

`web-task-stand-in`

## Situation

按“受限研究子 Agent”方案进行第二次真实测试，将一个 3DGS 压缩与端侧部署趋势任务投递到既有 ChatGPT 对话，并测量 Codex 主会话的可观察用量变化。

## What Happened

替身在约 13 秒内完成任务，返回了紧凑的三条趋势结论、六个来源和三个抽查点。最终结果本身约 2,168 个字符，但在任务运行期间使用正文读取接口检查状态时，接口重复返回上一轮很长的 3DGS 报告；预览和旧消息正文还可能同时出现。五小时账户用量显示从 33% 变为 34%，但界面没有提供可归因到单次任务的精确 token 数。

## Good Experience

研究委托、范围内自主检索、紧凑结论包和最小证据抽查均正常工作。替身没有返回完整检索过程，核心研究工作留在了独立聊天。

## Bad Experience

等待阶段与结果回收没有被严格分开。以会返回正文的读取操作轮询运行状态，会把旧答案和重复封装内容灌入主会话，抵消最终决策包带来的 token 节省。按“中文字符数”描述预算也没有约束链接和 Markdown 等完整载荷。

## User Interpretation

用户同意修订。应优先修复等待与回收协议，使状态探测只产生状态元数据，并把回传预算定义为包含链接在内的完整载荷预算。

## Other Notes

功能成功、上下文隔离和 token 减少仍应分别评价。本次结果不能证明 token 节省。
