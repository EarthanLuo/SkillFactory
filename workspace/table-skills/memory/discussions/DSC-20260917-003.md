# Discussion

## Starting Point

复核网页替身是否应继续保持通用网页入口，还是明确针对 GPT／Codex 桌面应用的会话能力设计。

## User View

用户要求增加约束：该 Skill 针对 GPT 桌面应用，应能使用快速对话，或者打开聊天对话进行替身操作。

## Challenges

- Skill 指令本身不能创造宿主未暴露的快速对话创建接口。
- 新建快速对话与打开既有聊天的隔离性不同；复用错误聊天可能带入无关上下文。
- 打开或发送到另一聊天不自动授予其修改本地项目文件的权限。

## What Changed

Skill 从泛化的网页聊天入口收窄为桌面应用原生会话控制优先：先探测并使用新快速对话；无法新建时，列出、选择并打开既有聊天；两者都不可用时明确报告能力缺口并提供手动任务包，不冒充已自动执行。

## Agreement

- 该 Skill 面向 GPT／Codex 桌面应用，不以通用浏览器自动化作为默认实现。
- 优先创建隔离的快速对话，并保存真实会话身份后再发送。
- 使用既有聊天时必须按明确标题或标识选择；存在歧义时让用户选择。
- 主任务继续承担协调和结果核验，目标聊天不会因被打开而自动获得额外写权限。

## Unresolved

- 不同桌面版本是否暴露稳定的新建快速对话接口，仍需在实际运行时探测。
- 任务记录模板与独立验收材料是否加入 Skill 目录，尚未由用户确认。

## Decision

`ADAPT`

按用户明确要求增加桌面应用与会话路由约束。
