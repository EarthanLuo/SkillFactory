# Chat Research Stand-in（聊天研究代理）

## Skill 用途

`chat-research-stand-in` 用于把一个边界清晰、研究量较大的任务委派给独立的 ChatGPT 桌面端对话，然后只恢复并核验一个紧凑的决策包，不把完整工作记录导入主任务。

这是一个实验性的桌面端 Skill。它的目标是保护主任务上下文，同时保留主任务和用户对最终决策及项目权限的控制。

## 安装

通常通过 Codex 的 **Plugins Directory** 安装包含它的 `Skill Foundry` 插件。如果使用 fork 或本地 marketplace，先运行 `codex plugin marketplace add <owner>/<repo>`，重启 Codex，再选择对应 marketplace 并点击 **Install**。单独使用时请复制完整目录，不要只复制 `SKILL.md`，因为工作流需要自带辅助脚本。

## 适用场景

适合在以下情况下使用：

- 研究目标和材料范围可以明确限定；
- 任务足够复杂，值得协调另一个对话；
- 结果可以压缩为带证据的决策包；
- 桌面端能够创建、识别、打开并读取 ChatGPT 对话。

如果只是短问题、持续依赖本地文件变化、需要频繁澄清，或必须携带大量当前上下文，应继续在主任务中完成。

## 标准流程

1. 选择新的 Quick Chat，或核验用户明确指定的已有 ChatGPT 桌面对话。
2. 准备任务包：目标、验收标准、权威材料、约束、研究范围、委派权限、输出格式、证据预算和禁止动作。
3. 除非用户明确授权，不要发送任务包。
4. 记录唯一任务 ID、执行路线、对话身份和提交状态。
5. 如果主机支持，在一次有界的等待中等待结果；超时不明确时不要重复提交。
6. 只恢复提交后与任务 ID 匹配的最新助手结果，删除主机内部引用占位符，不要把原始全文带回主任务。
7. 按照所需证据和项目状态核验重要主张。
8. 返回紧凑的采用说明：已核验结论、限制、产物和下一步。

## 自带辅助脚本

- `scripts/stand_in_package.py` 用于准备任务包，并提供确定性的 `probe`、`extract`、`budget`、`clean` 和 `ledger` 操作。它不会发送消息、浏览网页、核验事实或授权修改。
- `scripts/host_wait.mjs` 用于主机侧的有界等待，需要桌面主机注入原生的 `readThread` 操作。

没有 Python 时仍可手动遵循本 Skill；辅助脚本不是硬性依赖。

## 硬性边界

- 不用于普通浏览、通用浏览器自动化、Astra 测试或 API Conversation。
- 桌面 ChatGPT 对话不是 API 的 `conv_...` 对象。
- 准备任务包不等于获得发送授权。
- 代理只能在限定范围内研究；未经额外授权，不得改变目标、修改本地文件、联系第三方、花费资金、处理凭据或代替用户做最终决定。
- 任务发送成功不等于任务完成，返回答案也不等于证据已核验。
- 没有可重复评估时，不要宣称节省了 token 或提高了质量。

## 可移植性

这是一个自包含 Skill。复制或安装时，应保留 `SKILL.md`、本 README 和 `scripts/` 下的两个脚本，不要让它依赖项目的 `memory/` 目录或其他 Skill。
